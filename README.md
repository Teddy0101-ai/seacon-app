# 航运特训 · Seacon

《主流船型必须搞懂的知识白皮书》的**闯关训练版**。分模块、小步快跑，用来把知识真正记住。

- **11 个单元 / 38 节课 / 159 道题** — 每节 3—6 题，一次 2 分钟
- 题型：判断、选择、填空、配对、数量级判断、排序、多步情景、**产出题**
- **产出题不给选项**——先自己说，再对参考要点，三档自评。占全库 12.6%
- **344 条术语速查**，中英文都能搜
- **间隔重复**：答对一次不算学会，题目会按 1 / 3 / 4 / 6 / 9 / 15 天回来考你
- 答错**当场回炉**（隔 3 题、隔 9 题各考一次），并进错题本
- 每节课 5 颗心，**不跨天锁死**——想练多少练多少
- 结算页显示**首答正确率**和**产出率**，回炉做对的不算
- **可装到 iPhone 主屏当原生 App，断网也能用**

## 怎么练最有效（读这一段就够）

1. **按顺序走。** 上一单元做完 70% 才解锁下一单元——这不是限制，是因为不先把角色分清楚，后面会一直卡。
2. **每天先点「错题」。** 那里是错题 + 今天到期的题混在一起，比重刷新课有用得多。
3. **产出题不要跳。** 那是全库唯一逼你「张开嘴」的题型。选择题答对只说明你认得出。
4. **自评要诚实。** 放水的代价是它会在你真忘了的时候突然回来。

零构建、零依赖、纯静态。没有后端，没有任何网络请求，进度全部存在本机浏览器里。

## 一、部署到 Vercel

本仓库是**纯静态**的，不需要任何构建步骤。

1. 打开 <https://vercel.com/new>
2. 在 **Import Git Repository** 里找到 `Teddy0101-ai/seacon-app`，点 **Import**
   - 第一次用要先点 **Adjust GitHub App Permissions** 授权 Vercel 访问这个仓库
3. 三项设置：

   | 项 | 填什么 |
   |---|---|
   | Framework Preset | **Other** |
   | Build Command | **留空**（把 Override 开关关掉） |
   | Output Directory | **留空** |

4. 点 **Deploy**

一分钟出 `https://xxx.vercel.app`。

**之后每次 `git push`，Vercel 会自动重新部署**——这是选 GitHub 而不是拖拽的唯一理由，但也是最重要的理由。

### 更新内容的完整流程

```bash
# 1. 改题目
#    编辑 build_data.py

# 2. 重新生成（两个都要跑，缺一不可）
python build_data.py
python build_assets.py

# 3. 推上去，Vercel 自动部署
git add -A && git commit -m "更新题库" && git push
```

1. 用 **Safari**（必须是 Safari，Chrome 不行）打开部署好的网址

## 五、改内容

**改题目** → 编辑 `build_data.py`，然后：

```bash
python build_data.py
python build_assets.py     # 必须一起跑，见下方说明
```

题型写法：

```python
tf("这句话对不对？", 1, "解释")                      # 判断：1=对 0=错
mc("问题？", ["选项A","选项B","选项C"], 1, "解释")    # 选择：最后一个数是正确选项的下标
bank("句子里挖 ___ 空", ["A","B","C"], 2, "解释")     # 填空
pair([["左1","右1"],["左2","右2"]], "提示")           # 配对
num("这个数正常吗？", ["太低","正常","太高"], 1, "解释")  # 数量级判断（选项有序，不打乱）
order("按正确顺序排列", ["第一步","第二步","第三步"], "解释")  # 排序
scene("前情提要……", mc(...))                        # 给任意题加多步情景前情
```

> **⚠️ 出题时必须避开答案键偏倚。** `build_data.py` 打包时会自动打乱选择题选项顺序，
> 并对以下指标做断言，**偏了就打不出包**：
>
> | 指标 | 目标 |
> |---|---|
> | 判断题答案偏「错」的比例 | 40—60% |
> | 选择题正确项集中在同一位置的比例 | ≤ 40% |
> | 零知识策略（全选「错」+ 全选最热位置）命中率 | ≤ 45% |
>
> 这不是洁癖。2026-08-12 实测过一版：**一个对航运一无所知的人只用两条规则
> ——判断题一律选「错」、选择题一律选第二个——就能拿 82.6%，并通关全部 39 节，一节都不会挂。**
> 那样的题库测不出学习者会不会，还会让他以为自己会了，**比不学更糟**。
>
> 判断题的偏倚**没法自动修**（不能机器改写题干），只能人工把一部分题改成正向表述、答案为「对」。
> 另外写选择题时，**每个干扰项都要写成一个新人真会有的误解**，长度和正确项相当——
> 否则「选最长的那个」会变成新的作弊通道。

**改术语** → 改白皮书那边的 `terms_v2.json`，再跑 `build_assets.py`。

> **⚠️ 每次改完代码都必须重跑 `build_assets.py`。**
> Service Worker 的缓存版本号是按文件内容哈希生成的——不重跑，用户浏览器会一直用旧缓存，
> 你改的东西不会生效。这个坑本地实测踩过。

## 六、为什么这样设计

这一版是三轮评估后重做的，几个反直觉的选择值得说明：

**为什么心数不按天回满。** 原来是每天 5 颗，用完等第二天。问题是它每天最多只允许你错 5 次——
而**错误恰恰是学习价值最高的事件**。更糟的是心数归零后即使全部答对也过不了任何一节课。
现在改成每节 5 颗 + 答错当场回炉，错误的代价是「多做两遍」，不是「今天不许再学」。

**为什么答对一次不算学会。** 原来错题答对一次就永久移出错题本。但典型路径是
「答错 → 看解释 → 30 秒后答对 → 毕业」——那次答对时答案还在工作记忆里，
不提供任何长期记忆证据。现在答错要重走学习步，答对则按 1 / 3 / 4 / 6 / 9 / 15 天递增回来。

**为什么加产出题。** 再认（认出正确选项）和产出（从零说出来）是两条不同的记忆通路。
用选择题训练、再用选择题测量，会稳定产生「学过、认得、但张不开嘴」。
而老板问「这条船的红线日租是多少」时，你不能说「给我四个选项」。

**为什么结算页不显示总正确率。** 显示的是**首答正确率**——回炉做对的不算。
一个答错三次、蒙对一次的人本来会看到 100%，那是最有害的一种反馈：
**它把「知道自己不会」的人变成「以为自己会」的人。**
